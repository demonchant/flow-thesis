# Candidate Concepts and Idea Gate

**Scoring:** 1 = weak, 3 = viable, 5 = strong. Scores are comparative judgments from inspected official product/API surfaces, not measured user research or official hackathon weights. The total out of 80 is a prioritization aid only; any critical gate failure rejects a concept regardless of total.

Weights use the standard's fifteen core idea dimensions: problem/user value, technical depth, AI necessity, statefulness, UW integration, differentiation, demo/evidence, failure handling and time feasibility. Detailed dimension scores are in the table; all candidates are bounded to read-only analysis and no financial advice/trading.

## Individual candidate briefs (26-part review)

Every concept is assessed with the same 26 prompts: (1) problem, (2) user, (3) UW overlap, (4) endpoints, (5) indispensability, (6) AI work, (7) deterministic work, (8) state, (9) async behavior, (10) triggering event, (11) change detection, (12) re-evaluation, (13) historical evaluation, (14) failure modes, (15) failure detection, (16) recovery, (17) independent verification, (18) evidence, (19) hardest technical problem, (20) hardest AI problem, (21) hardest data problem, (22) hardest reliability problem, (23) 60-second demo, (24) judge memory, (25) thin-wrapper failure, (26) differentiation. To keep the concept comparisons readable, each numbered brief covers those prompts in compact field groups; “unknown” means it requires confirmation rather than assumption.

## UW endpoint-contract update for all candidates

The official Flow Alerts operation page was opened and inspected after drafting the candidate cards. It documents `GET /api/option-trades/flow-alerts`, the `ticker_symbol`, time-window, filter and `limit` parameters (default 100, maximum 200), and fields including `created_at`, `all_opening_trades`, `has_multileg`, `has_singleleg`, `has_sweep`, `total_ask_side_prem`, `total_bid_side_prem`, `total_premium`, `volume_oi_ratio`, `underlying_price`, and `option_chain`. The detail route `GET /api/option-trades/flow-alerts/{id}` returns the alert plus constituent trades and a `has_more`/`older_than` pagination path. It explicitly states Flow Alerts are not limited by the 14-day custom-alert cap. These docs are generated operation pages; the raw OpenAPI YAML and actual trial key response are still not available here. [Flow Alerts](https://api.unusualwhales.com/docs/api/option-trade/flow-alerts), [Flow Alert by ID](https://api.unusualwhales.com/docs/api/option-trade/flow-alert-by-id)

UW's `flow-alerts` WebSocket page says personal streaming is only available on the Advanced plan. Thus the MVP should use REST polling and accurately display polling freshness; do not depend on trial WebSocket access or claim sub-second/continuous real time. It also means stream-based candidates lose feasibility at the Basic trial tier. [Flow-alert WebSocket access](https://api.unusualwhales.com/docs/websocket/flow-alerts)

The flow-alert filter page lists boolean/default behaviors (for example the `all_opening` flag), so the adapter must send explicit chosen filters after exact semantics are validated. Otherwise implicit defaults can shape the cohort and invalidate evaluation. OpenAPI YAML remains a pre-live contract check.

## Decision

Candidate 1 scores **41/45** on the nine comparative scorecard dimensions (not a prediction of winning). Its strongest advantages are indispensable UW observations, durable state, falsifiable transitions, a one-minute live/replay proof and measurable evaluation. Main risks: UW flow already has alert/configuration products, history/window entitlements are uncertain, AI necessity must stay bounded, and API terms may constrain the required public demo.

**Hard-gate conditions before shipping:** successful API smoke check for exact routes/fields/entitlements; no secrets in browser/client or repo; event replay with a data freshness model; no trading/financial recommendation; written answer on public display/derived-data permissions or a compliant public evidence mode. These conditions do not block building offline core logic, but public live-data deployment is not approved by this analysis alone.
